# 块属性驱动的编号状态 —— 实施方案

## 一、背景与目标

### 现状

`skip / lock / repeat` 三种状态存放在外挂的 SandboxStorage JSON 里，按块 UUID 索引：

```
{图谱目录}/assets/storages/left-sidebar-enhance/{图谱名}.json
{ "blockStates": { "块uuid": "skip" } }
```

问题：

1. **状态不跟块走**——复制、粘贴、移动块会产生新 UUID，状态直接丢失。
2. **额外生命周期**——需要处理图谱名、加载失败回滚、15 秒后孤儿数据清理、旧版页面迁移。
3. **不可见、不可查**——用户无法通过属性查询筛选，也无法手动修正。

### 目标

1. 用 Logseq 原生块属性 `numbering::` 承载状态，彻底移除外挂存储。
2. 新增第 4 种状态 `skip-subtree`：跳过自身且整棵子树都不编号。
3. 状态在 UI 中尽量不可见（对齐 `collapsed:: true` 的观感）。
4. 不改动现有编号算法、区间分类、H4 格式、skip/lock/repeat 的既有语义。

### 已确认的决策

| 项目 | 决定 |
|---|---|
| 属性键 | `numbering` |
| 隐藏方式 | 插件注入 CSS（兜底）+ 设置面板提示用户改 `config.edn` |
| 旧数据迁移 | **不迁移**。旧 JSON 保留在磁盘不删除，插件不再读取 |
| 实施顺序 | 先出本文档，确认后再改代码 |

## 二、状态模型

同一个属性键 `numbering`，四个合法值：

| 值 | 语义 | 自身文本 | 编号序列 | 子标题 |
|---|---|---|---|---|
| `skip` | 跳过编号 | 移除已有编号 | 不参与、不占序号 | **照常编号**（继承父级编号前缀） |
| `skip-subtree` | 跳过编号且子块也跳过 | 移除已有编号 | 不参与、不占序号 | **整棵子树不编号**，标记时递归移除子树内已有编号（`locked` 块除外） |
| `repeat` | 重复编号 | 改写为上一个同级标题的编号 | 不递增 | 正常递归 |
| `locked` | 锁定编号 | **不修改** | 提取其编号，后续兄弟从该值 +1 | 正常递归 |

约定：

- 值统一小写、去空格。
- 非法值（拼错、空值、其他内容）按"无状态"处理，插件不报错、不修改用户数据。
- 四种状态互斥。在右键菜单里切换到另一个状态时**直接覆盖**，不需要先清除。

### 清理策略（cleanup = subtree）

标记跳过类状态时，对**已有编号文本**的处理：

- `skip`：只移除被标记块自身的编号前缀。
- `skip-subtree`：移除自身编号，并**递归移除整棵子树内所有标题的编号前缀**。
- 递归清理时**跳过 `locked` 块**：锁定语义是"插件永不修改该块"，清理同样属于修改。
- 清理只动每块的第一行编号前缀，块内其余行（含 `numbering::` 属性行）原样保留。
- 递归清理逐块 `await updateBlock`，每处理 10 个块让出一次事件循环，避免大批量写入卡住 UI；单块失败不回滚，但要在结束消息中报告失败数量。

### 与旧命名的对应

| 旧值 | 新值 |
|---|---|
| `skip` | `skip` |
| `lock` | **`locked`**（改名） |
| `repeat` | `repeat` |
| — | `skip-subtree`（新增） |

因为决定不迁移，旧 JSON 里的 `lock` 不需要兼容映射，代码中只认 `locked`。

## 三、数据层设计

### 3.1 模块归属

重写 [src/heading-numbering/blockStates.ts](../../src/heading-numbering/blockStates.ts)，保留文件名以减少 import 改动；**删除** [pageWhitelist.ts](../../src/heading-numbering/pageWhitelist.ts)（它是 blockStates 的重复副本，全仓库 0 引用）。

### 3.2 导出 API

```ts
export type NumberingState = 'skip' | 'skip-subtree' | 'repeat' | 'locked'

/** 属性键（统一小写） */
export const NUMBERING_PROP = 'numbering'

/**
 * 同步解析：从块树节点的 properties / content 中读取状态。
 * 编号算法主流程使用，零 IPC。
 */
export const parseNumberingState = (
    properties: Record<string, unknown> | undefined,
    content?: string
): NumberingState | null

/**
 * 异步读取单个块的状态。仅右键菜单使用。
 */
export const getBlockNumberingState = async (
    blockUuid: string
): Promise<NumberingState | null>

/**
 * 写入 / 清除状态。state 为 null 时移除属性。
 */
export const setBlockNumberingState = async (
    blockUuid: string,
    state: NumberingState | null
): Promise<void>
```

### 3.3 读取实现要点

**主路径：复用块树里的 `properties`。**

`getPageBlocksTree()` 返回的每个块自带 `properties`，而 [findHeaders.ts](../../src/page-outline/findHeaders.ts) 的 `buildHierarchicalHeaders` 已经把它透传到 `HierarchicalTocBlock.properties`。因此编号流程读取状态**不需要任何额外 API 调用**。

属性键在不同模式下形态不稳定，必须做容错查找：

```ts
// 伪代码
const findProp = (props: Record<string, unknown>, name: string) => {
    // 兼容 'numbering' / ':numbering' / ':logseq.property/numbering'
    for (const key of Object.keys(props)) {
        const tail = key.split('/').pop()!.replace(/^:/, '').toLowerCase()
        if (tail === name) return props[key]
    }
    return undefined
}

const normalize = (raw: unknown): NumberingState | null => {
    const v = Array.isArray(raw) ? raw[0] : raw          // 多值属性取第一个
    if (v === null || v === undefined) return null
    let s = String(v).trim().toLowerCase()
    s = s.replace(/^\[\[|\]\]$/g, '')                     // 去掉 [[ ]]
    return (s === 'skip' || s === 'skip-subtree' || s === 'repeat' || s === 'locked')
        ? s as NumberingState
        : null
}
```

**兜底路径：从 `content` 的后续行解析。**

防止某些版本/模式下 `properties` 未及时回填。标题块内容形如：

```
## 2.3 标题正文
numbering:: skip-subtree
```

用 `/^numbering::\s*(\S+)\s*$/mi` 在 `content` 的**第 2 行起**匹配。第一行是标题，绝不能参与匹配。

**判定顺序**：`properties` 命中就用它；未命中再看 `content`。

### 3.4 写入实现要点

```ts
if (state === null) await logseq.Editor.removeBlockProperty(uuid, NUMBERING_PROP)
else                await logseq.Editor.upsertBlockProperty(uuid, NUMBERING_PROP, state)
```

两点必须遵守：

1. **写入后必须重新取块再改文本。** `updateBlock(uuid, content)` 是整体替换，属性靠 content 里的 `numbering::` 行承载。如果拿旧的 `block.content` 去重写标题，刚写进去的属性会被抹掉。
2. **编号流程只改第一行。** 现有所有 `updateBlock` 调用都是 `[新第一行, ...lines.slice(1)]`，天然保留属性行——前提是 `node.content` 来自最新的 `getPageBlocksTree()`。本次改造**不得**在编号流程中途写属性。

### 3.5 旧数据

- 不读取、不迁移、不删除。
- 删除 `src/index.ts` 中 15 秒后执行的 `cleanUpOrphanedData()` 调用；删除 `loadConfigFromPage()` 在 `initHeadingNumbering()` 和 `onCurrentGraphChanged` 中的调用。
- 旧 JSON 文件静置在 `assets/storages/left-sidebar-enhance/`，不影响功能。文档（readme）里说明一句即可。

## 四、隐藏方案

属性必须能被插件 API 读取（隐藏只影响 UI），所以隐藏分两层：

### 4.1 插件 CSS（兜底，自动生效）

替换 [headingButtons.ts](../../src/heading-numbering/headingButtons.ts) 顶部现有的 `heading-num` 隐藏样式：

```css
.block-properties [data-ref="numbering"],
.block-properties .property-pair:has([data-ref="numbering"]) {
    display: none !important;
}
```

效果：阅读态属性面板不显示；进入块编辑时仍能看到 `numbering:: skip` 这一行文本。这是浏览器层能做到的极限。

### 4.2 `config.edn`（彻底隐藏，用户手动）

在插件设置面板的编号相关区域增加一段说明文字（`type: 'heading'` 或 description）：

```
如需彻底隐藏该属性（编辑时也不显示），请在 config.edn 中加入：
:block-hidden-properties #{:numbering}
```

注意：

- 插件**不得**自动修改用户的 `config.edn`。
- 该配置会让属性在 UI 中完全不可见、不可手动编辑，但 API 与 `{{query (property numbering skip)}}` 查询仍然正常。
- 隐藏后状态只能通过右键菜单查看/切换，因此菜单操作后的 `showMsg` 提示要明确写出当前状态。

## 五、编号算法改造

只改 [index.ts](../../src/heading-numbering/index.ts) 的 `processSiblings` 状态分支，其余（层级遍历、H4 格式、区间分类、子标题固定规则）**保持不动**。

改造前：

```ts
const headingNumProp = getBlockHeadingState(node.uuid)   // 读外挂缓存
if (headingNumProp === 'skip') { ...递归 children... continue }
if (headingNumProp === 'lock') { ... }
if (headingNumProp === 'repeat') { ... }
```

改造后：

```ts
const state = parseNumberingState(node.properties, node.content)   // 零 IPC

if (state === 'skip-subtree') {
    // 自身与整棵子树都不动：不清理、不递归
    continue
}

if (state === 'skip') {
    // 语义不变：自身不编号，子标题继承父级前缀继续编号
    if (node.children?.length) await processSiblings(node.children, parentNumberStr, ...)
    continue
}

if (state === 'locked') { /* 原 lock 分支，仅改名 */ }

if (state === 'repeat') { /* 原样保留 */ }
```

`skip-subtree` 的插入位置必须在 `level > 4` 判断之后、其他状态分支之前，且**直接 `continue`，不进入 children 递归**。

第 2.6 节的"子标题固定编号规则"分支不受影响。

## 六、右键菜单

[headingButtons.ts](../../src/heading-numbering/headingButtons.ts) 从 3 项扩展到 4 项：

| 菜单项 | 当前状态 | 操作 |
|---|---|---|
| 跳过/恢复自动编号 | `skip` | 清除属性 |
| | 其他/无 | 设为 `skip`，并移除自身标题编号 |
| 跳过整棵子树/恢复 | `skip-subtree` | 清除属性 |
| | 其他/无 | 设为 `skip-subtree`，并移除自身标题编号（子块不动） |
| 重复编号/取消重复 | `repeat` | 清除属性 |
| | 其他/无 | 设为 `repeat` |
| 锁定编号/取消锁定 | `locked` | 清除属性 |
| | 其他/无 | 设为 `locked` |

统一流程（顺序不可颠倒）：

```
1. getBlock → 校验是否为标题（/^#{1,6}\s+/）
2. setBlockNumberingState(uuid, 目标状态)
3. 若目标状态是 skip / skip-subtree：
     重新 getBlock（拿到含属性行的最新 content）
     → 移除第一行开头的编号
     → skip-subtree 额外递归遍历子树逐块移除编号（跳过 locked，每 10 块让出事件循环）
4. cleanupBlockProperty（清理历史遗留的 heading-num 属性，保留）
5. 延迟 300ms → applyHeadingNumbersToPage(当前页)
6. showMsg 明确提示当前状态，例如：
   「已设为跳过整棵子树（子块将不再编号）」
```

跨状态切换直接覆盖，不做"必须先取消"的限制。

`findPrevSiblingNumber`（未被调用的死函数）在本次改造中一并删除，避免与新状态模型混淆。

## 八、边界与已知风险

### 8.1 属性名冲突

`numbering` 是通用词。若用户已在其他插件/笔记中使用 `numbering::`，会互相覆盖。**已确认按用户要求使用 `numbering`**，在 readme 与设置说明中提示冲突风险。

### 8.2 `updateBlock` 吞属性

见 3.4。这是本次改造最容易回归的点，验证用例必须覆盖"改完编号后属性仍在"。

### 8.3 数字开头标题（既有缺陷，本次不修）

`## 2023 年总结` 会被现有正则当成"编号 2023"处理，`skip` 操作也会吞掉 `2023`。本次改造不改变该行为，但改造完成后这个问题仍然存在，需单独排期。

### 8.4 仅文件型图谱生效

`applyHeadingNumbersToPage` 开头的 `isFileBasedGraph` 判断保持不变。数据库模式（0.11+）仍不执行编号。属性 API 本身在 DB 模式可用，属于后续独立议题。

### 8.5 旧状态丢失

不迁移意味着改造后所有已有 `skip/lock/repeat` 标记失效，用户需要重新右键标记。这是已确认的取舍。

### 8.6 属性写入会改动笔记文件

文件型图谱下 `numbering::` 会写进 `.md`，使用 Git 同步时每次右键都会产生一次文件变更。

### 8.7 递归清理的放大风险

`cleanup = subtree` 会在一次操作中改写多块文本，现有"数字开头标题被吞"的正则缺陷（见 8.3）会被同时放大到整棵子树。**实施前必须用测试图谱验证，不要直接在主笔记图谱上首次运行。**
